# Security Policy

## Reporting Security Issues

If you discover a security vulnerability in Amplyfive, please report it responsibly.

**Do not** open a public issue or pull request for security vulnerabilities.

Instead, please:
- Open a draft security advisory using GitHub's [Security Advisory](https://github.com/amplyfive/skills/security/advisories) feature, or
- Send an email to [your-email@example.com] with details about the vulnerability

Include as much information as possible:
- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Any suggested mitigations (if known)

We will acknowledge receipt within 48 hours and provide regular updates on our progress toward a fix.

## What Counts as a Security Issue?

Security issues include but are not limited to:
- Code execution vulnerabilities
- Authentication and authorization flaws
- Sensitive data exposure or leakage
- Dependency vulnerabilities with known exploits
- Injection vulnerabilities (XSS, SQL injection, etc.)
- Misconfigurations that could lead to security issues

Normal bugs, feature requests, and non-security-related issues should be reported through regular GitHub issues.

## Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial assessment**: Within 7 days
- **Fix release**: As soon as feasible, based on severity
- **Public disclosure**: After a fix is released and users have had reasonable time to update

We appreciate responsible disclosure and will work with you to ensure issues are addressed appropriately.
